## 3.5 用户报的两个真机现象（2026-09-15 已定位，**未修**）

用户在 v0.4.0 上发真实回合时看到两件事，各自查到了**代码级成因**（不是猜）：

1. **正文里出现「调用工具的过程」**（截图里是 `💻 terminal` + 一段代码块）。
   成因：核心会把工具进度**塞进流式帧文本**（`gateway/run_turn_runner.py::_progress_build_message`
   对 terminal 类工具返回的就是「emoji + 工具名 + 围栏代码块」这个形状），而工具**先于任何回答正文**
   发生的回合里，核心的合成式 `"\n\n---\n".join(p for p in (accumulated, progress) if p)`
   **只有 progress 那一半、没有分隔符**（`accumulated` 为空）⇒ R11-A7 的证明式剥离
   第 ③ 条（「我们的累积非空且是帧前缀」）**必然不成立** ⇒ 按 fail-open 原样渲染
   ⇒ 用户看到的就是那一整段核心进度。真机自检行 `正文剥进度=0` 与之一致
   （2026-09-15 16:39 那次：`面板=有（rounds=4 tools=3）· 本回合帧=6 · 正文剥进度=0`）。
   **可行的修法**（插件侧，仍然不动核心配置）：把证明条件换一个更强的形态 ——
   「**我们的累积为空** + 有工具窗口 + 累积完整」时，帧文本里**不可能**有模型写下的正文
   （核心把同一个 chunk 既投给消费者、又投给我们的钩子，见 `agent/stream_delivery.py:314`）
   ⇒ 整帧都是核心注入的进度，可以渲染成占位符而不是进度文本。
   ⚠️ 前提要单独验：钩子队列**会不会静默丢包**（`agent/plugin_stream_hooks.py` 的 enqueue
   是否无界/是否吞异常）—— 会丢的话这条证明就不成立，得退回去。
2. **正文里出现一个黑色方块**（用户截图 1 末尾 `…当前实测 29°C、■`）。
   成因：核心的**流式光标**常量 `gateway/config.py:450 DEFAULT_STREAMING_CURSOR = " ▉"`
   （U+2589），由 `gateway/stream_consumer.py:790-798` 在**每一帧可见文本末尾**追加、
   **收尾帧不加**（注释写明 `unless finalizing`）。飞书客户端把它渲染成一个实心方块 ⇒
   用户看到「黑方块」。它只出现在流式过程中（收尾那一帧整卡替换会去掉）。
   可行的修法：只在**非收尾帧**剥掉末尾这一个已知光标（收尾帧按理不含它，剥了也无害）。
   ⚠️ 风险面：模型自己正文末尾正好是 U+2589（概率极低，且只影响中间帧一个字形）。

两条都**还没修**：属于 R11-A7 的边界补强，要先满足「钩子不丢包」这个前提、再配单测与变异。
