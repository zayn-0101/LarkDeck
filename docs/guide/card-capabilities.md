# 卡片能力与限制

本文面向在飞书里使用 LarkDeck 的用户：说明一张卡片能做什么、怎么做，以及客户端或服务端不支持时会出现什么。

## 回复卡片与长回答

- 回合开始、正文还没有第一个字时，LarkDeck 先建一张卡，正文留空并显示加载动图（不可用时用静态图标）；首段正文到达后移除提示。
- 模型文字到达后，同一张卡原地长大；工具调用不再另发消息，而是合入同一张卡。
- 回答结束：完成绿边、失败红边、中止黄边。页脚显示状态、耗时、模型与上下文用量。
- 回复卡使用飞书卡片 2.0，才能用流式打字机和可折叠面板；澄清卡可以单独选 2.0 或 1.0，见下。

## 流式打字机

- 默认传输 `native_transport: cardkit`，文字逐字出现，这是真正的逐字效果。
- 当前结构化引擎不会因 `native_transport: patch` 切换传输；自动降级时才可能改用同卡整卡替换。
- `streaming_print_ms` 控制客户端打字机间隔，`0` 关闭；它只影响节奏，不影响发送速度。
- 任何一步失败，LarkDeck 都会优先保住消息：先尝试用同一张卡继续更新（可能失去逐字动画），再不行才改用官方纯文本或编辑消息。

## 第 N 轮思考（round）

- 一段连续推理被正文或工具事件打断，就算一轮（round），标题形如“第 N 轮思考 · 1.6s”。
- 当前正在生成的轮自动展开，已结束的轮自动折叠；你手动展开或收起后，后续 token 不会把它顶回去。
- 推理正文要两个开关同时成立：Hermes 侧 `plugins.stream_reasoning_deltas: true`，插件侧 `show_reasoning` 为 `auto`（跟随 Hermes）或 `on`。
- 只开显示、没开 Hermes 增量时，面板仍会显示工具和“思考 X.Xs”的耗时摘要，但不显示推理文字；`/larkdeck status --detail` 会说明原因。

## 执行详情（panel）

- 推理与工具合并成卡片底部一个可折叠面板，摘要形如 `💭 思考 1.6s · 🛠️ 工具执行 · 3 步`。
- 每个工具步骤显示动作、参数预览、耗时和状态：运行中、成功、失败、被阻止、超时、取消等。
- 参数预览会被截短，明显是凭据的片段会自动打码；工具输出只在错误等需要排查时展开。
- 步骤很多时，更早的步骤会折叠；结构化面板最多显示最近 20 步和 20 轮推理，
  `max_panel_steps` 可以进一步收紧步数。每轮推理和工具结果块分别受 `max_reasoning_chars`、
  `max_tool_result_chars` 限制。
- `unified_panel: false` 可以完全关闭它；运行中与收尾的展开状态分别由 `streaming_panel_expanded`、`panel_expanded` 控制。

## 澄清卡（clarify）

模型需要你选择时，LarkDeck 会把问题做成交互卡：

- **2.0（默认）**：问题下先列出编号选项，再给下拉框；单选卡带一个自由输入框，多选卡是勾选列表加“提交”按钮。
- **1.0（`clarify_dialect: "1.0"`）**：每个选项一个按钮，另有“其他（我直接输入）”；点击同样会回到服务端。
- 点击成功时，待答卡原地变成绿色的“已确认”卡，主卡同时显示“已收到你的选择，正在继续…”。
- 点击迟到或重复时，卡片保持原样，只弹一条提示“这条澄清已被处理或已过期”，不会把已确认状态退回待答。
- 其他未生效的点击会弹提示说明原因；不会静默无反应。
- 澄清卡发送失败时，会改用官方文字提问，你直接回复文字即可。

## 失败、降级与限制

- **卡片整张失败**：改用官方纯文本或编辑消息。内容不会丢，但那一刻没有卡片、动画和按钮。
- **CardKit 元素通道失效**：同一张卡继续用整卡替换更新，卡片和内容都在，只是不再逐字；装饰元素可能冻结到收尾帧一次补齐。
- **消息被撤回或删除**：这一帧停止写入；之后是否补发由 Hermes 核心决定，所以可能看到一条新消息。
- **客户端不支持 2.0 组件**：部分组件可能不渲染或降级展示，具体形态由飞书客户端决定；升级客户端通常能恢复。
- **超长回答**：一张卡装不下时自动封卡并开新卡。旧卡末尾写“（续下一条）”，新卡只显示剩下的那段；内容不会重放或丢失。
- **已知边界**：分卡后 `/stop` 只重绘最新一张；页脚与自检记录是进程级累计，多会话并发时不区分会话。AI 正文不翻译；只有带原生 i18n 字段的界面节点跟随客户端语言，markdown 中的工具动作 / 状态词及部分中文提示语言固定。

配置项与示例见 [配置参考](configuration.md)；卡片不出现在预期状态时见 [故障排查](troubleshooting.md)。
