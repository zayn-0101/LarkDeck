# 故障排查

本文面向遇到卡片异常的用户：按“症状 → 根因 → 排查 → 修复 → 预防”定位插件加载、卡片更新、错误码、思考显示、点击与长回复分卡问题。

## 插件加载超时 / 飞书退回纯文本

- **症状**：启动日志有 `[larkdeck] 启动自检失败` 或插件加载超时；所有回复都是官方纯文本，没有卡片。
- **根因**：多发生在旧版插件配 Hermes 0.21.4：插件的平台注册与 Hermes 延迟平台加载互等，直到插件加载超时；也可能是官方 `feishu` 平台没启用或被其他插件抢占。
- **排查**：`hermes --version`；`grep '\[larkdeck\]' ~/.hermes/logs/agent.log | tail`；确认官方 `feishu` 平台可用（凭据已配置），且没有另一个改源码或抢占 `feishu` 的插件共存。
- **修复**：升级 LarkDeck 到当前版本并 `hermes gateway restart`；去掉 `plugins.load_timeout_seconds: 0` 之类的绕过配置；确保官方飞书平台启用。
- **预防**：跟随当前发布版本；不要在 Hermes 0.21.4+ 上跑旧版插件；一次只装一种飞书卡片方案。

## 卡片不更新

- **症状**：卡片停在“正在生成…”，或只更新到一半；也可能先看到卡片、后来变成一条条纯文本。
- **根因**：纯推理阶段正文还没开始长，Hermes 不会发新帧，卡片等待是设计行为；或 `cards` / `native_streaming` 被关；或启动时接管失败；或卡片消息被撤回 / 删除；或某次更新失败后改用普通消息发送或编辑。
- **排查**：连续发几条普通消息；在 `/larkdeck status` 看钩子是否 8/8；需要逐条记录时用 `/larkdeck status --detail` 看最近写卡帧数是否增长；日志里查 `[larkdeck]` 的“卡片更新未成功”“native 流式帧”“掉回纯文本”记录。
- **修复**：只是长时间思考就继续等；配置关了就把 `cards`、`native_streaming` 开回并重启；接管失败按上一条处理；消息被删则重新发一轮，是否补发由 Hermes 决定。
- **预防**：流式中不要撤回或删除卡片；升级后必须重启网关；不要手工替换运行中的卡片消息。

## `300313` 元素不存在

- **症状**：卡片突然不再逐字，之后更新变少；或某个装饰元素不再变化。日志出现 `300313`。
- **根因**：插件要写的 CardKit 元素 id 在当前卡片里不存在，常见于卡片结构已被整卡替换、流式会话错位、消息被改动，或运行中换了插件代码。
- **排查**：`grep '300313' ~/.hermes/logs/agent.log | tail`。如果坏的是正文字元素，插件会降级成整卡替换、同一张卡继续更新；如果只是某个装饰元素被点名，插件只冻结它并保留逐字。
- **修复**：通常无需操作，收尾帧会用整卡替换补齐。若每轮都出现，重启网关让新卡使用当前结构，并确认只有一份当前版本的插件。
- **预防**：升级后重启；不在流式中整卡替换 / 删除消息；不在回合运行中热换代码。

## `230099` 卡片被拒

- **症状**：卡片发不出去，整条回复变成纯文本；日志出现 `230099`，可能带内部错误码。
- **根因**：飞书确定性地拒绝这张卡，原样重发不会成功。常见是卡片版本混用、字段不受支持，或卡片超过上限；同一条日志里的内部码可区分：`11310` 元素超限、`200861` 该卡片版本不支持此能力、`200621` 卡片 JSON 解析失败。
- **排查**：用 `/larkdeck status --detail` 看“错误码”与最近失败原因；`grep '230099' ~/.hermes/logs/agent.log | tail` 读完整原因。判断是普通回答也失败，还是只在超长 / 复杂回合失败。
- **修复**：先升级并重启，排除旧版结构问题；长回合可设 `unified_panel: false` 或降低 `max_panel_steps` 等上限；确认配置类型正确。普通回答持续失败时保留日志反馈。
- **预防**：跟随当前版本；不要手工改卡片结构；长回复交给自动分卡。

## 思考不显示

- **症状**：执行详情里有工具步骤和“思考 X.Xs”摘要，但没有推理正文。
- **根因**：Hermes 默认不发送推理增量（`plugins.stream_reasoning_deltas` 关闭）；或 Hermes `display.show_reasoning` 关闭；或插件 `show_reasoning: off`；或当前模型没有产生推理。
- **排查**：在 `/larkdeck status` 看“推理显示”结论（开 / 关）；需要原因时用 `/larkdeck status --detail`，它会写明模式与原因（例如“Hermes 未发送 reasoning delta”）；核对 `~/.hermes/config.yaml` 里的两个开关。
- **修复**：在 `~/.hermes/config.yaml` 开启：

  ```yaml
  plugins:
    stream_reasoning_deltas: true
  display:
    show_reasoning: true
  ```

  然后重启网关；空闲时在飞书发 `/reasoning on` 也可以。插件的 `show_reasoning: auto` 会跟随，若要强制则设 `on`。
- **预防**：保持 `show_reasoning: auto`；不要同时在 Hermes 或插件侧把推理关掉。

## 澄清卡点击没反应

- **症状**：点澄清卡（clarify）的选项或“提交”后卡片没有任何变化，也没有提示。
- **根因**：插件未接管或点击回调未接上；卡片交互事件未订阅到；点击已过期或重复；旧版本上主卡更新有延迟。
- **排查**：先看卡片本身有没有变成“已确认”。若是“卡片变了、主卡没变”，升级版本即可。若弹出“已被处理或已过期”，说明是重复点击，属预期。若完全无反应，用 `/larkdeck status --detail` 看点击回调与命令注册，日志里查 `[larkdeck] clarify 点击`；同时确认网关在线。
- **修复**：升级 LarkDeck 并重启；重新发起一次澄清；必要时运行 `hermes gateway setup` 重新配置飞书应用与卡片交互订阅；仍不行就直接回复文字作答。
- **预防**：保持版本与网关在线；不要连点；不要移除应用的卡片交互事件订阅。

## 面板空白

- **症状**：执行详情有标题但展开后是空的，或该出现面板的真实回合没有面板。
- **根因**：旧版在收尾帧快照为空时会渲染空面板；也可能钩子没挂上、这一回合没有任何工具或推理数据、`unified_panel` 被关，或这是系统提示 / 命令回复（按设计不渲染面板和页脚）。
- **排查**：`/larkdeck status` 看钩子是否 8/8；用会调用工具的请求复现；日志里查“面板为空”诊断行，它会带会话 / 绑定信息；核对 `unified_panel: true`。
- **修复**：升级到当前版本并重启；想看推理就同时开启 `plugins.stream_reasoning_deltas`；真实回合持续空白时保留诊断行反馈。
- **预防**：跟随当前版本；升级后重启；别把系统提示当普通回合。

## 长回复切卡

- **症状**：回答写到一半出现第二张卡；第一张卡末尾有“（续下一条）”，不再继续更新。
- **根因**：飞书单卡有硬上限（估算用 128000 字节，递归元素 200 个）。插件在正文到硬上限一半时就封掉当前卡，开新卡只写剩下的那一段，避免整张卡发送失败。
- **排查**：这是预期的分卡行为。确认第一张卡有“（续下一条）”、第二张卡从剩余内容开始，没有重复或缺失；若内容重复、丢失或每次分卡都报错，再收集日志。
- **修复**：不需要修复；不要在两卡之间手工编辑或删除消息，避免后续写入找不到目标。`/stop` 只会重绘最新那一张。
- **预防**：让长回复自然分卡；如果卡片本身很大，可关闭 `unified_panel` 或降低面板限额，给正文留更多空间。
