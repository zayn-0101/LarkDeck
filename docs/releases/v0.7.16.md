# v0.7.16 — 回合进行中，卡片明确说"我在忙"

## 这一版解决什么

用户报的原始问题（2026-10-07）：**"当多回合、且需要我做选择时，我选完，卡片 Footer 会显示已完成，但其实工具调用还在继续"**（v0.7.14 / v0.7.15 已修掉当时的两个入口）。

接着发现同一族的第二处：**回合进行中时，页脚与"已完成"只差一个 ✅**。模型先输出一段话、还要继续思考或调工具的那几秒里，页脚是空的 —— 看起来和终稿几乎一样，用户无法判断"它还在跑"还是"它答完了"。本版把这一档补上明确的进行中状态词，并给"长时间没有进展"补一条降级判据。

## 行为细节

- **进行中的三种状态词**（只在页脚首段，位置不变）：
  - `✍️ 正在生成`：回合还活着、面板里没有正在跑的工具（模型在写）；
  - `⚙️ 正在执行工具`：回合还活着、面板里有工具在跑；
  - `⏸ 等待你的选择`：澄清卡在等**人**（与"等工具"区分）。
- **判据只有一个出口**（`_ld_live_status`），顺序写死：结局词最先判 → 收尾乐观终态 → 等人 → 收尾但工具还在跑（`⏸ 等待中`）→ 进行中词 → 说不出来就**留空**（宁可少说一句，也不说假话）。
- **降级（`⏳ 等待响应`）只作用于"存活 + 无工具"这一档**：默认 `200` 秒没有任何进展证据（成功流式帧 / 工具钩子 / 上游心跳 / API 请求）才降级；工具在跑、等人、收尾帧都不降级。写 `0` 或负整数关闭；非法值退回 `200` 并留一条 60 秒限流的 WARNING。
- **收尾之后同回合继续**：收尾帧写的 ✅ 会被后续帧回到**同一张卡**改写回进行中词（不再永远停在已完成）。恢复走整卡 patch 车道（收尾已经关掉逐字通道），所以这一段没有打字机效果，这是有意取舍。
- **失败回合优先**：面板标 `error` / `stopped` 且**是本回合**时，即使流还活着、这一帧不是收尾帧，也先写结局词；回合身份对不上（上一回合的残留）则不扣到本回合头上。
