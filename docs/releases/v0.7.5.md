# v0.7.5 — 长任务心跳进主卡面板 + seed 防闪旧

- **长任务心跳不再插中间卡**：默认模式（`long_running_notifications` 非 generic）下，
  Hermes 每 180s 的 `⏳ Working — N min — …` 心跳会合入当前结构化主卡的
  `collapsible_panel` 标题（`⏳ Working … · 原摘要`），不再新建独立 Working 卡；
  最终答案仍写同一张主卡，心跳不碰正文。若当时没有 active 主卡，只建**一张**专用
  静默卡并复用；多条 active、degraded、面板关闭、刚 finalize 的安静窗口内一律抑制。
- **追问不再先闪上一回合工具步骤**：新回合 seed 帧不再读取上一回合的 panel 快照，
  只建空面板壳（面板元素仍在，首帧起填当前回合数据）。
- **明确不做**：不同入站回合各自一张卡。2026-09-23 日志与飞书消息列表证据显示，
  长任务后出现的第二张「答案卡」是后台进程完成通知（`Watch pattern notification`）
  触发的独立新回合，不是同轮重复 finalize；插件侧不做跨回合合并/抑制，避免吞掉真实回答。
- **已知限制**：`long_running_notifications: generic` 的任意心跳文案仍走 v0.7.4 静默卡，
  暂不进面板；同轮 native finalize 失败 / boundary 多卡需上游 `_stream_turn_id` 或
  `get_stream_message_id` 接口后再评估。
- **升级**：`git pull` → `hermes gateway restart`；回退 `git checkout v0.7.4` → 重启。
- **已知限制**：① `long_running_notifications: generic` 文案不进面板；② 无 active 主卡时
  的专用 Working 卡在真实终稿后仍留在时间线（不删/不合并）；③ 首个 live 帧抢在
  `on_stream_start` 前到达的毫秒级竞态仍属已知残余。
- **门禁**：冻结提交 `3dce128`：定向 331/331、V075 38/38 red-assert、preflight 589/589、
  `run_fast --full` 8/8、golden 一致；全量 6 分片 **577/577 red-assert** + 12/12 对照、
  `n_inh=0`、墙钟 1282.4s。
