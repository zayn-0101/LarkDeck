# LarkDeck v0.7.2

真机反馈收敛：页脚去短码、加载指示改成「会动、无文字」、工具图标逐条对齐 CLS、
澄清卡表单提交契约、以及 14:44 那条「卡片 + 纯文本」并存的真根因修复。

## 用户可见的变化

### 1. 页脚不再有 🔖 短码

用户口径（2026-09-21）：**「我从来没有提过这个要求」** —— 它当初是内部审计为「截图 ↔ 日志对齐」
加进来的。现在页脚字段对齐同类插件（CLS / aiduPOP / FC）：

```
✅ 已完成 · ⏱ 10.4s · 🤖 deepseek-flash · ctx 20.5k/1m
```

短码**只保留在日志自检行**（`卡片=<6 位>`），截图与日志仍然可以对上；卡片头 / 正文 / 面板 /
折叠提示 / 收尾 patch **一律不出现**（`test_v4_17b` 按状态 × 有无 message_id 全枚举扫整卡 JSON，
再扫建卡实体、每一次元素 batch、收尾整卡 patch）。

### 2. 加载指示：会动、无文字

用户口径：「『正在加载上下文…』**不对**，aiduPOP 那个是会动、无文字的状态指示」。
现在建卡插入的元素逐字段对齐 aiduPOP `_loading_element`：

```json
{"tag": "div", "element_id": "loading_hint",
 "icon": {"tag": "custom_icon", "img_key": "img_v3_02vb_…", "size": "16px 16px"},
 "text": {"tag": "plain_text", "content": " "}}
```

那个 `img_key` 是 aiduPOP / CLS / FC 三家**共用的同一张动图**（三家都没有自己上传）。
真机探针（`om_x100b643abd6394b0dfa26a200d65018`）用户目视结论：**① 会动** ✅。
首个正文 token 到达即删该元素；删失败会**换号重试**（同 uuid 重发会撞飞书 `200770`），
最多 3 次后放弃并留 warning（收尾整卡本来就不含它）。

### 3. 顶部状态条默认关闭

`card_status_header: false`（用户口径「顶栏默认不显示」）。想要旧观感把它设回 `true`。

### 4. 工具图标逐条对齐 CLS

主表 **28 条逐条等于** CLS `streaming/tooluse.py::_TOOL_DESCRIPTORS`（含**顺序**：
精确匹配 或 `alias_` 前缀匹配，未知工具回落 `setting-inter_outlined`）。
唯一有意偏差登记在案：`terminal`（CLS 表里没有它，而 Hermes 的 shell 工具**就叫** `terminal`）。
`tests/check_cls_alignment.py` 直接解析 CLS 源码比对 —— CLS 侧改了别名，我们这边会红。

### 5. 澄清卡：表单提交不再「空提交」

官方契约：`option` / `options` / `input_value` **只在组件未嵌入 form 容器时**返回；
一旦放进 form，答案只在 `action.form_value[组件 name]`（submit 按钮的 `value` 是空的）。
现在 `value` 为空、答案只在 `form_value` 的提交形态已经走 e2e（用**真 SDK payload 类**构造，
与真机 WS 反序列化同源）：能解除网关阻塞、原地回执换卡、重复提交只给 toast。
组件级 `behaviors`（当前生产卡形态）路径不变。

### 6. 修复：卡片与「⏳ Working — …」纯文本并存（灰气泡）

14:44 那条纯文本的**真根因**不是内核心跳，而是我们自己的卡片被飞书拒收后 fail-open：
`collapsible_panel` 的直接子元素曾经是 `plain_text`（非法）—— 工具步数 > 20 触发折叠提示时
`300313` ⇒ 收尾整卡 `200621` ⇒ 核心回落 `send()`。已改成 `markdown`（变异 `V4-33` 实红）。

## 排障增强（非用户可见）
