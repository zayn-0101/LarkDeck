# v0.7.22 — 心跳那条路径也会续命了

## 修了什么

### 1. 心跳刷新先撞到期 ⇒ 不再直接降级
0.7.20 的续命只装在**帧路径**上。如果先撞上「元素通道到期（约 10 分钟）」的是**心跳**那条
**同步**写，它会直接把面板判死、整回合退回旧渲染 —— 于是又回到「面板拍平」。
现在两条路径共用同一个入口：**先续命（结构化整卡 patch），失败才降级**。

### 2. 修正 0.7.20 的一个自身缺陷
0.7.20 的续命守卫是「卡片里没有面板 ⇒ 放弃续命（比旧渲染更差）」。但**回合刚开始**时
本来就没有面板（模型还在憋第一段、还没有任何工具/思考数据）—— 于是那种时刻续命会被
错误放弃。现在只有「**本来有面板、却被降载摘掉了**」才放弃。

### 3. `status --detail` 多一行自查证据
```
元素通道到期：续命 2 个回合 · 降级 0 个回合
```
续命成功后观感上**看不出**发生了什么（这是设计目标），所以给你一个能查的地方。
默认视图不加这一行。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行版本都应是 `0.7.22`；
2. 跑过超长回合后，`/larkdeck status --detail` 里看「续命 N / 降级 N」；
3. 面板应始终是「每轮一个可折叠子面板」。

## 诚实边界

- 心跳那条路径**目前没有可判别的单测**：现有心跳夹具不进入元素车道（`engine_stamp`/`card_id`
  前置不满足），所以我删掉了那条「看起来能测其实测不到」的用例与变异，并在计划里登记 ——
  **没有测试覆盖就等于没被证明**，这条要等夹具补齐。
- 最后一级兜底仍是旧渲染（markdown 面板）：续命失败时你会看到拍平，但不会丢内容、也不会卡死。
