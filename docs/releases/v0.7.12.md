# v0.7.12 — 状态卡默认精简，细节进日志

## 这一版解决什么

v0.7.11 的状态卡信息完整，但**太长、太技术**：一张卡上同时出现适配器类名、缺失接口、
信号契约、探测契约、模块世代、失败原因与错误码明细。这些是排障用的，不是用户每次看
状态都想读的内容。这一版把默认卡收成**结论**，细节交给主动请求的视图与日志：

- **默认 `/larkdeck status`**：七行表格 —— 平台接管、钩子、推理显示、最近写卡、
  写卡失败 / 掉回纯文本、错误码、已运行。每格都是「标记 + 值」，异常行标签标红。
- **`/larkdeck status --detail`**：展开完整诊断 —— 能力与链路、能力探测（运行环境 /
  适配器 / 会话归属 / 缺失接口 / 信号契约 / 探测契约）、六条记录（含时刻、次数与失败原因）。
- **技术细节写入日志**：每次查询都会把诊断、探测、记录三组事实原文写进
  `~/.hermes/logs/agent.log`，可用 `grep '[larkdeck] status'` 查；日志失败不影响命令。
- **默认卡给出去处**：页脚写明「详细诊断已写入 `agent.log`；完整视图：`/larkdeck status --detail`」。

## 行为细节

- 两个视图读的是**同一份**现场数据（诊断行 / 探测快照 / 记录行），区别只在版式与展开程度；
  精简视图只截掉括号里的原因与明细，不改任何计数。
- 事实纪律不变：没记录写「无记录」、零计数写「0 次」、绝不写「正常 / 健康」；`⚠️` 只由
  明确异常触发。进程级口径说明在默认卡上仍然保留。
- 若精简视图解析不出某条应有的事实，会退回完整视图 —— 宁可长一点，也不静默少一行。
- `status` 后面跟不认识的后缀（如 `status wat`）仍然明确报「不认识的参数」，不静默忽略。
- 其它命令、卡片、面板、配置键均无改动。
