# v0.7.14 — 选择之后：页脚不再说假话，续写回到同一张卡

## 这一版解决什么

多回合里需要你做选择时（工具审批、澄清提问），答复之后卡片会出现三处别扭。其中两处是这一版修的：

1. **页脚说「✅ 已完成」，同一张卡的面板里却写着 `Running`（运行中）。**
   上游在回合**中途**就会给流式卡发一帧「收尾」（`stream_consumer._handle_approval_boundary`，
   注释原文 "The stream is never kept open across a prompt"）—— 那一刻工具正卡在等你批准，
   插件却把「收尾」当成了回合结束，于是写死「已完成」。
2. **续写另开一张卡。** 审批通过后，上游把流式输出降级成「答案生成完时一次性发送」；
   这条终稿过去会重新建卡，于是你看到两张卡，而且两边的面板把同一批工具步骤各画了一遍。

修完之后：

- 只要面板里还有**运行中**的工具，卡片状态就显示 **`⏸ 等待中`**（灰边），工具收口后才变成
  `✅ 已完成`（绿边）；没有再出现「已完成 + Running」这种自相矛盾的卡面。
- 审批通过后的终稿**写回原卡**：正文、面板、耗时、状态一次对齐，不再多出第二张卡。

## 行为细节

- **只改状态词，不改数据**：工具的生死照旧由 `pre_tool_call` / `post_tool_call` 决定；
  这一版只是不许把「还没结束」渲染成「已结束」。正常回合（工具都收口后才收尾）的观感**不变**：
  依旧是 `✅ 已完成 · 时长 · 模型 · ctx`。
- **续写认回合，不认时间**：边界收尾那一刻记下这张卡与**回合身份**；终稿到达时只在
  「还是同一个回合」时才写回原卡 —— 你等审批等了多久都不会失效，而下一个回合永远不会被写进旧卡。
- **失败即回落，绝不丢消息**：写回原卡的整卡更新失败（限流、卡片被撤回、结构不兼容）时，
  照旧新发一条 —— 消息一定会到你面前，只是回到这一版之前的样子，并留下日志
  （`grep '边界续写' ~/.hermes/logs/agent.log`）。
- **澄清路径不受影响**：澄清边界本来就以「同一张卡继续」处理（流不关闭），这一版只是把
  同一套「工具还在跑就不说已完成」的判断也用在它身上。

## 已知边界

- 若某个工具的收尾事件在飞书侧真的丢了（`post_tool_call` 没到），卡片会停在「⏸ 等待中」
  而不是谎报「已完成」——这是有意的：宁可少说一句，也不说假话。
- 正文里出现命令行那种情况（你截图里的第二张图）**不在这一版范围**：那需要先拿到你机器上的
  日志才能定性（是上游把工具进度拼进了帧，还是模型自己写了命令块）。等你把日志片段发来，
  再决定怎么修。
- 正文超过单卡上限触发**卡链**（封旧卡 + 开新卡）时，被**封掉**的那张卡仍是「✅ 已完成」+「（续下一条）」：
  它确实不会再被写入、后续内容在新卡上。这是沿用行为，这一版没改 —— 退役卡该显示哪个词是另一个决定。
