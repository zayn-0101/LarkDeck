# v0.7.13 — 长回合心跳说人话：短句 + 跟随客户端语言

## 这一版解决什么

长回合（模型迟迟不出字）时，卡片标题会出现上游 Hermes 的心跳原文：

```
⏳ Working — 9 min — iteration 5, waiting for provider response (streaming)
```

它是英文、含内部计数（`iteration`），还带着与页脚重复、且最长滞后 180 秒的时长；中英混排
又会把 `🛠️ 工具执行 · 6 步` 挤出标题。这一版把它归一化成短句，并跟随飞书客户端语言：

| 场景 | 中文客户端 | 英文客户端 |
|---|---|---|
| 等模型响应 | `⏳ 等待模型响应 · 第 5 轮` | `⏳ Waiting for the model · round 5` |
| 工具在跑 | `⏳ 正在执行 terminal · 第 5 轮` | `⏳ Running terminal · round 5` |
| 认不出的活动 | `⏳ 处理中` | `⏳ Working` |

## 行为细节

- **位置不变**：仍是折叠面板标题（`⏳ … · 🛠️ 工具执行 · 6 步`）；正文出现或回合收尾时照旧清除，
  续卡不继承。
- **时长不再进标题**：页脚耗时每 3 秒刷新、起点一致；上游的整分钟数最长滞后 180 秒，
  两个数并存只会互相矛盾。
- **双语靠飞书原生 `i18n_content`**：服务端只发一份卡，客户端按自己的界面语言挑一条 ——
  不需要检测系统语言，也不需要发两张卡。
- **上游原文进日志**：`grep '上游心跳原文' ~/.hermes/logs/agent.log` 可查原词（上游改文案时能追溯）。
- **兜底**：解析失败、形状变化或活动改词 → 显示通用短语；**任何情况下都不把英文原文回显到卡面**。
- **已知边界（沿用）**：Hermes 把 `long_running_notifications` 设为 `generic` 时，心跳文案不带
  `⏳ Working — ` 前缀，本插件识别不到（既有已知限制，README 已记）；无活跃主卡时创建的专用
  静默卡正文是 markdown 元素，飞书不支持在其上做双语（`i18n_content` 的既定边界）。
