# v0.7.20 — 长回合的面板不再被拍平

## 你遇到的现象

一个跑得比较久的回合（比如 5 分钟思考 + 18 个工具）里，面板突然「拍平」了：
每一轮思考变成一坨 markdown（`**第 N 轮思考 · 3.0s**` + 正文 + `…已省略 N 字符`），
**嵌套子面板全部消失**。

## 原因（有真机实测）

飞书给一张**流式卡**的元素通道**只有约 10 分钟寿命**（我们实测 **606 秒**，纯写元素也一样）。
到期之后再按元素更新，飞书回 `300309`。旧版本这时会把整回合切成「整卡更新 + 旧渲染器（markdown 面板）」
—— 卡没丢、内容没丢，但**观感被拍平**了。

## 修好之后

吃到 `300309` 时**先续命**：用结构化内容对同一张卡做一次整卡 patch，并重新声明流式态
（真机实测：元素通道随即恢复）。之后继续按元素更新 ⇒ **面板、每轮一个可折叠子面板、打字机效果都在**。

三级兜底照旧保留：续命失败（例如卡片降载后连面板都装不下）⇒ 旧的整卡渲染 ⇒ 再失败才纯文本。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行的版本都应是 `0.7.20`；
2. 跑一个超过 10 分钟的长任务（或多轮工具调用）：面板里应当**始终**是「每轮一个可折叠子面板」，
   不再出现整块拍平；日志里会出现 `元素通道到期…已用结构化整卡 patch 续命`（限流 60 秒一条）。

## 诚实边界

- 这条路我们只实测到「**一次**到期 + **一次**续命成功」；连续多次续命未实测，所以续命失败时会**回落**
  旧渲染（不会更差，也不会卡死）。
- **面板装饰写**那条**同步**路径（心跳驱动的面板刷新）比帧路径先撞到期时，本版仍是直接降级
  （帧路径才是你两次事故的实际触发点）—— 这条已登记为下一步（v0.7.21）要收口的残留路径。
- 已经被遮蔽/被中止的**旧进程**不会自己报警，重启网关后新版本才生效。
