# v0.7.7 — 澄清选择后主卡即时更新

## 这一版解决什么

用户点选澄清卡（Clarify）后，澄清卡本身会变成「已确认」，但**主卡片**在一段时间里仍然显示：

- 正文：`💬 等待你的选择...`
- 面板：`clarify · Running`

看起来像点击没有生效。真机日志显示点击已经成功（`resolve_gateway_clarify` 已提交），
只是 `clarify` 是**阻塞工具**：用户点完后，工具要等自己的同步回调返回才会触发
`post_tool_call`；实测这段等待 **36.96s**。主卡在这段时间的显示停留在边界占位文案上。

## 修复方式

1. **结构化车道不再把 clarify 边界当成普通收尾**：识别核心写入的
   `💬 等待你的选择...`，不关闭主卡流，只把正文改写为 `⏳ 等待你的选择…`；
   主卡流状态保留，点击后才有对象可以原地刷新。
2. **点击成功立即乐观更新面板**：把 `clarify` 步骤标为完成（`ok`）；点「其他（我直接输入）」
   时保持 `running`、显示「等待输入」，不假装完成。
3. **异步刷新主卡正文**：在网关 loop 上写回 `✅ 已收到你的选择，正在继续…`
   （元素通道被其它路径关闭时回落同一张卡的整卡 patch）。后续 delta 继续更新同一张卡。
4. **真实结果覆盖乐观状态**：`post_tool_call` 到达时按 `tool_call_id` 找到同一行并覆盖
   （失败/取消也能覆盖），不会多出一条重复的 clarify 步骤；提交未生效的迟到重复点击
   仍只回 toast，绝不把已确认卡退回待答。
