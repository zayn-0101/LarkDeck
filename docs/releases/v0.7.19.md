# v0.7.19 — 页脚不再显示「别的会话的模型」

## 你遇到的现象

在 NAS 上和 Hermes 对话：新回合**刚开始**时，页脚显示的模型是 `Agnes 3.0 Flash`（那是
「AI 日报」定时任务用的模型），聊了几轮、调过工具之后又变回自己的模型
（截图里是 `DeepSeek V4.1 Flash`）。

## 原因

页脚读的是一份**进程级**快照：「全进程最后一条收尾的 API 请求」。同一个 Hermes 里跑定时任务
或后台复盘时，它们各自的 API 请求会把这份快照改掉 ⇒ 你这条新消息的页脚在**本回合自己第一条
请求收尾之前**，显示的是**那个会话**的模型。

而 Hermes 本来就在回合开始时把模型告诉插件了（`on_stream_start` 载荷里有 `model` / `provider`），
只是之前没人记下来。

## 修好之后

- 页脚用**本回合**的模型：回合一开始就显示对，换回合即清空；
- 拿不到本回合模型时才退回进程级快照，而且**必须同一个会话** —— 不是同一个会话就整段不显示
  （连 `ctx` 用量一起），宁可少一段，也不显示别人的数字；
- `/larkdeck status` 里的指标**仍然是**「最近一条 API 请求」，那是它本来的语义，没有改。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行的版本都应是 `0.7.19`；
2. 让定时任务（或另一个会话）跑一次**别的模型**，然后回到本会话发一条新消息：开头页脚的模型名
   应当**立刻**是本会话的模型，或者暂时不显示模型 —— 都不该出现那个别的模型名。

升级后没生效？看[故障排查](../guide/troubleshooting.md)里的「升级没生效」一节 —— 自检行**行末**
应带 `插件 v0.7.19 @ …`。

## 诚实边界

- 这是**显示**层修复：页脚的模型名不再撒谎；它不会改变任何实际调用用的模型。
- 已经被遮蔽/被中止的**旧进程**不会自己报警，重启网关后新版本才生效。
