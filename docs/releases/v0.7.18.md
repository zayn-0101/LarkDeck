# v0.7.18 — `/stop` 之后不再挂着「Running」

## 你遇到的现象

多回合回答里，工具正在执行时点 Stop：页脚已经写着「已中止 · 1m32s」，工具面板里却还有一行
`vision_analyze · Running` —— 看起来还有动作在跑，卡片自相矛盾。

## 原因

`/stop` 会让内核**直接放弃**当前这一帧（abandon），正在跑的那个工具因此**永远等不到**
「工具结束」回调（`post_tool_call`）。那一行的状态就永远停在 `running`，而页脚是另算的，
所以两处打架。

## 修好之后

中止时会把**仍在运行**的工具行标成 `Cancelled`（灰色）：

- 已经跑完（`✓`）/ 失败（`Failed`）/ 跳过（`Skipped`）的行**不受影响** —— 它们是事实，不许改写；
- 中止时那一行不留耗时（没跑完就不编一个数字）。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行的版本都应是 `0.7.18`；
2. 随便开一个会调工具的多回合任务，工具在跑时点 `/stop`：面板里那一行应是灰色 `Cancelled`，
   而不是蓝色 `Running`。

升级后没生效？看[故障排查](../guide/troubleshooting.md)里的「升级没生效」一节 —— 自检行**行末**
应带 `插件 v0.7.18 @ …`。

## 诚实边界

- 这条修的是**卡片显示**：工具是否被内核真正掐断由 Hermes 决定，卡片只是不再替它「假装还在跑」。
- 已经被遮蔽/被中止的**旧进程**不会自己报警，重启网关后新版本才生效。
