# v0.7.21 — 「自我改进回顾」通知不再是一长串

## 你遇到的现象

后台自我改进回顾跑完后，飞书里来一条：

```
💾 自我改进回顾：技能 'jav-openaver-management' 已修补 · 技能 'repair-quote-review' 已创建 · 技能
'repair-quote-review' 已写入 (references/joycon-repair.md) · 技能 'repair-quote-review' 已修补
```

一行到底、没有换行、没有分组 —— 读不动。

## 原因

内核用 `" · ".join(...)` 把每条动作拼成一个 `summary`，再套一句
`💾 自我改进回顾：{summary}`（`locales/zh.yaml` 的 `display.review.summary_callback`）。
卡片只是原样显示这段文本 —— 排版不是卡片选的，是内核拼的。

## 修好之后

插件在**渲染层**（只对这条通知）重排：

```
💾 自我改进回顾 · 2 个技能

**jav-openaver-management**
· 已修补

**repair-quote-review**
· 已创建
· 已写入 (references/joycon-repair.md)
· 已修补
```

- **只改这一条通知**，正常回答一个字都不动；
- 同一技能的多个动作合并到它名下；路径原样保留；
- **认不出的条目一条不丢**（比如「记忆已更新」会列在「其余：」下面）；
- 标题语言跟随通知本身（英文通知就出英文标题）；
- 顺带：这条通知被加进「系统提示」负清单 —— 即使哪天内核不再打标记，它也不会被误判成回合卡。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行版本都应是 `0.7.21`；
2. 等下一次后台复盘（或直接看历史那条）：应是分组列表，不再是 ` · ` 连到底。

## 诚实边界

- 这是**显示层**改进：内核文案本身没变，其它平台（CLI/TUI）仍是原来的一行。
- 解析是**保守**的：只认 `技能 'X' 动作[(路径)]` / `Skill 'X' verb[(path)]` 这两种形状，
  认不出就原样保留 —— 宁可不美化，也不吞掉内容。
