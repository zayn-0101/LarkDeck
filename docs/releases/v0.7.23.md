# v0.7.23 — 心跳那条路径，这次真的接上了

## 修了什么

### 1. 0.7.22 的修补接错了分支
0.7.22 宣称「心跳撞到期也先续命」，但它只改到了心跳的**合并分支**（`_ld_hb_merge_stream`）；
心跳**实际走的那条**（`_ld_heartbeat_tick`）仍是老写法：**直接判死面板 + 降级**。
所以你那个「长时间没输出 ⇒ 面板拍平」仍可能发生。现在两条都接进同一个入口。

### 2. 澄清/审批点击后的整卡兜底不再关掉流式位
兜底过去用 `streaming_mode=false` 发整卡 —— 按真机实测（V1b/V2b），这会**关掉元素通道**，
于是下一帧白挨一次 `300309`（虽然会自动续命，但那是白折腾）。现在保持流式位，`card_id` 继续有效。

### 3. 测试补硬
- 新增「心跳撞到卡级死法**必须**走统一入口」——过去这条路径**没有**可判别用例；
- 新增「续命**成功** ⇒ 绝不许降级」——这条才钉得住「先续命再降级」的顺序；
- `V4-20` 变异重新锚定到 `if _revived:`：上一版它只能把测试搞崩（不算抓住），现在**真的被判红**。

## 自查（30 秒）

1. `hermes plugins list | grep larkdeck` 与 `/larkdeck status` 首行版本都应是 `0.7.23`；
2. `/larkdeck status --detail` 里看 `元素通道到期：续命 N · 降级 N`；
3. 长回合（>10 分钟）后，面板仍应是「每轮一个可折叠子面板」。

## 诚实边界

- 心跳/续命这些分支**仍然只能在真实长回合里被最终验证**；单测只能证明「走了哪条路、状态记对没记对」。
- 续命失败时仍会回落到旧渲染（markdown 面板）：那是最后一级兜底，不会丢内容、不会卡死。
