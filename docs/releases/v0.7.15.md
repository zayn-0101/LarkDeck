# v0.7.15 — 审批之后的工具进度不再跑到正文里

## 这一版解决什么

上一版修掉了「页脚谎报已完成」和「续写另开一张卡」，这一版修掉同一场景里的第三处：
**卡面正文里出现一段命令行代码块**（`💻 terminal` + 围栏 + 命令），有时还多出一张只写着工具进度的卡。

根因不在模型，也不在卡片渲染，而在「审批之后上游换了一条通道」：

1. 等你做选择时，上游会给流式卡发一帧**中途**收尾（`stream_consumer._handle_approval_boundary`），
   **并关掉本回合的 native 流**；
2. 之后工具进度不再进卡片，改走「进度气泡」通道（`gateway/run_turn_runner.py::send_progress_messages`
   → `_send_progress_text` → `adapter.send`），内容就是 `💻 terminal` + 围栏 + 命令
   （连续 terminal 时连 `💻 terminal` 头都没有，正文直接以代码围栏开头）；
3. 这条消息的 metadata **不带 `_interim_send`**（`ctx._progress_metadata` 只装会话/线程路由），
   而插件判「这是不是回合产出」只认 `_interim_send` + 已知系统提示前缀 ⇒ 判成回合
   ⇒ 建成一张新卡：正文是那段命令，还带上页脚与面板。

真机证据（2026-10-03 23:58 按下审批之后，`~/.hermes/logs/agent.log.1`）：

```

23:59:27 send 判定 turn=True guarded=False keys=[]
23:59:28 出站=card … 前置="``` echo '== A. opencode_affinity 源码（看 H"
00:00:19 出站=edit  … mid=om_…49d1d 前置="``` echo '== A. opencode_affinity 源码（看 H"
```

## 行为细节

- **不出站、不建卡、也不回落纯文本**：命中「这是上游工具进度气泡」就什么都不发。
  同一批工具行本来就由 `pre_tool_call` / `post_tool_call` 钩子画进卡面板，心跳也在持续刷新
  ⇒ 这条消息是**纯重复**，删掉它用户不会少看到任何信息。返回值照心跳语义（成功、**故意不带 message_id**），
  上游因此不会进入 edit 路径。
- **判据可证伪，而且是 fail-open**：只看两件事 ——
  ① 文本形状：整段要么是进度行，要么是**闭合**的代码块（复用正文净化那套 `_looks_like_core_progress_only`）；
  ② 面板里**确实**有同名工具在 `running`（只有裸代码块时这条尤其必须）。
  证明不了（有散文、围栏没闭合、面板里没有运行中的同名工具）就照常出卡 ——
  宁可多一张卡，也**绝不吞**模型自己写的代码块。
- **不再碰原卡**：这道闸在「同回合续写」之前，所以这类气泡也不会被当成终稿写回原卡正文。
- **工具名单同源**：判定用的工具名单统一走 `_panel_tool_names`（`_panel.answer_tools(chat)`，
  即正文累积选中的那个会话桶），与正文净化同一处，不会出现「看 A 会话的工具、剥 B 会话的正文」。

## 已知边界

- 上游这条通道**没有给进度气泡打标记**（`ctx._progress_metadata` 里只有线程 / 路由信息），
  所以插件只能靠形状 + 面板交叉验证来认。上游哪天补上 `_interim_send`，这条识别就可以退化成常规分支。
- 钩子没到（面板里看不到那个工具在 `running`）时形状判据会 fail-open ⇒ 退回这一版之前的样子
  （多一张卡），不会静默吞文本。
- 卡链封掉的旧卡仍显示「✅ 已完成 +（续下一条）」：沿用行为，这一版没改。
- 这条闸只作用于 `send()`（新消息 / 续写）；流式车道的逐帧写入本来就不读上游合成文本（own 模式）。
