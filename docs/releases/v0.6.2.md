# LarkDeck v0.6.2

修复：模型未写正文时的**多行**核心工具进度不再进入答案正文；面板默认启用状态颜色与
12px 记法字号。

## 问题

v0.6.1 只处理“第一行就是 `terminal` / 裸代码围栏”的单行进度帧。真机上更常见的是
模型先连续调用多个工具、迟迟不写正文：Hermes 核心的 `_tool_progress_lines` 在首个
正文 delta 之前只追加不清空，于是同一帧是**多行块**：

```
🔍 Searching the web for …
📄 Reading https://…
🖥 terminal
```

```
ls -la
```

旧判据只看第一行，首行是 friendly verb 时不匹配，整帧照旧落进答案正文。
2026-09-18 的真机回合状态库与收尾自检 `正文剥进度=0` 均指向这一形态。

## 修复

- 正文净化的空累积分支改为**逐行识别整帧**：核心 curated verb、`{emoji} {tool_name}`、
  `{tool_name}: "…"` / `{tool_name}...` / `{tool_name}(…)`、完整代码围栏、
  `(×N)` 去重后缀、流式光标 `▉`、`⏳ Working — …` 长任务状态行。
- 保守护栏：只有**全部**非空行都能证明是核心进度、且没有 `---` 分隔符时才剥；任何一行
  不匹配则 fail-open。Markdown 标题 / 列表 / 模型散文（非 ASCII emoji 规则 + 核心 verb
  精确表）不会被误判。
- 裸代码围栏（没有显式 `🖥 terminal` 表头）必须与“terminal 工具仍在 running”交叉验证，
  避免模型答案的第一条代码块被当成连续 terminal 进度短暂剥空。
- 工具名单改用与累积正文**同一会话**的 `panel.answer_tools()`；归属不确定时 fail-open，
  不会拿另一个会话的 terminal 名单剥本会话正文。
- `check_hooks` 的前提核对改为使用核心真实的 `_progress_build_message` 产物，覆盖
  friendly verb + terminal 的多行真实帧。

## 面板颜色与字号

- `panel_color_tags` 默认从 `false` 翻为 `true`：依据飞书 Card 2.0 `markdown` 组件官方
  文档（支持 `<font color='red'>…</font>` 与 14 色枚举），状态词按语义上色
  （绿色 `Succeeded` / 青绿 `Running` / 红色 `Failed`·`Blocked`·`Timed out` /
  灰色 `Cancelled`·`Skipped`），工具细节行灰色。
- `text_profile` 默认从 `off` 翻为 `compact`：面板与页脚 `notation`（12px）、正文
  `normal`（14px）；只用官方文档列出的字号 token，原先 `compact` 里的 `x-small`
  已移除。
- 客户端不认颜色时可在配置显式写 `panel_color_tags: false` 回到纯文本降级。

## 边界

- 颜色与字号的**视觉**仍需真机截图确认；官方文档确认语法，不等于客户端一定渲染。
- `finalize=True` 帧仍永不剥离：核心在确定性帧失败后会用同一合成文本重发 finalize
  （`gateway/stream_consumer_transport.py`），保留进度行是防止不可逆吞正文的已知取舍。
- 上游若新增 curated verb，需在 `_CORE_PROGRESS_VERBS` 同步补；漏掉的动词在升级后
  会退回 fail-open（那一条进度可能短暂可见），不会吞正文。
- D1 的 header 实时局部更新仍为方案 c（未实现生产代码）。
