# LarkDeck v0.6.3

修复：长工具回合中，模型尚未写正文时卡片不再显示空白正文区。

## 问题

v0.6.2 把核心的多行工具进度从答案正文剥掉之后，空正文的流式中间帧会给 CardKit
`answer` 元素写一个空格。工具连续跑很多轮时，用户看到的是一张只剩折叠面板的空卡，
像卡住了（2026-09-18 真机复测反馈）。其他卡片方案在等待期至少会显示一个「正在生成」
占位。

## 修复

- CardKit 流式中间帧在正文为空时保留 `⏳ 正在生成…` 占位（复用 v0.4 起的
  `cards.answer_or_pending` 文案），正文 token 一到就被替换。
- 收尾帧（`streaming=False`）**不带占位**：真的没有正文的回合不能永远停在
  「正在生成…」。
- 面板/页脚/状态色逻辑不变；工具进度仍只在折叠面板里，不进答案正文。

## 验证

- `tests/test_units.py`：226/226 passed。
- `tests/check_override.py` / `check_hooks.py` / `check_clarify_e2e.py`：全部 EXIT=0。
- `tests/mutate_check.py --preflight`：399/399 锚点（392 变异 + 7 对照）。
- 定向变异 `CLS-42`（流式空正文写空格）与 `W6b`（正文内容被写成常量）均断言红。
- v0.6.2 的六分片全量证据仍见 `docs/audits/cls-ui/phase-4/v0.6.2/`；本次改动面
  由四门禁 + 定向变异覆盖。

## 边界

- 颜色/字号的实际渲染仍待真机截图确认。
- `finalize=True` 帧不剥进度（防不可逆吞正文的已知取舍）与上游新 verb fail-open
  边界同 v0.6.2。
