# LarkDeck v0.6.4

修复：core 持有“空白累积”时，带前导分隔符的多行工具进度不再进入答案正文。

## 问题

真实回合里 core 的累积可能只含空白（例如一个未被 hook 清洗掉的 leading newline）。
此时 `_compose_frame_content()` 会发出：

```
\n\n---\n
🔍 Searching the web for …
💻 terminal
```

```
cd /tmp && …
```

v0.6.2/v0.6.3 的正文净化看到 `---` 分隔符就 fail-open，于是答案区出现分隔线、
搜索行和 terminal 代码块（2026-09-18 15:17 真机截图）。这不是模型写的正文。

## 修复

- 累积为**空白**时，若帧以「纯空白前缀 + 核心分隔符」开头，先归一掉这个前缀再做
  逐行进度形状判定；能证明是核心进度就剥成占位。
- 分隔符之前只要有任何非空白正文，仍 fail-open：那是模型自己写的内容，一个字不动。
- 保留 v0.6.3 的 `⏳ 正在生成…` 占位：工具执行期间正文区显示占位，不显示空白或进度。
