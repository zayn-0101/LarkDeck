scope 永久零回调）。

## 1. 不变量（每步都要守）

1. 绝不改 Hermes 源码、绝不 monkeypatch；**双加载/世代更替是 Hermes 的行为，只能在插件侧防御**。
2. 卡片是增强不是替代：任何卡片路径失败必须 fail-open 回落 `super()`。
3. 私有名只允许出现在 `compat.py`；**不得硬编码关于 Hermes 内部结构的假设**（不变量 4：能力运行时探测；
   先例 `compat.accepts_positional`）。第 2 路审计的 H1 就是拿这条把它判掉的。
4. 不假设版本；能力运行时探测。
5. 每个修复都要有**能证伪的门禁**（撤掉必红）+ 尽可能的真机证据；**改断言必须重跑全量变异**。
6. 合并/变基/`--3way` 之后必须重跑全量变异（推论 26）。
7. **commit message 末尾附当次实测门禁数字**（`docs/lessons.md` 第 4 节）。
8. **改 `cards.py` 或任何卡片结构后必须跑 `tests/probe_render.py`**；改降载档位/状态色载体后
   `--stop-redraw` 与默认模式都要跑（`AGENTS.md:283,298`）。
9. 公开仓库红线：**不提交任何日志原文、真实 `oc_/ou_/om_/cli_` id**（`AGENTS.md:322`）；
   结案表只放**脱敏后**的行，并把红线扫描扩到 `docs/` 全量跑。
10. 破坏性操作/写操作先说清范围与**回滚点**（`AGENTS.md:323`）。

## 2. Phase A：世代更替的根治与防线

| 步骤 | 内容 | 回滚点 |
|---|---|---|
| **A0 状态清点** | 把**进程内可变状态**列成表并逐条决定「共享 / 无关」：`panel._STATE/_CHAT_SESSION/_LAST_ACTIVE_BOX/_LOCK`、`context._STATUS/_LATEST/_MAX_CACHE/_RETRY_AFTER/_ALIASES/_MAX_OVERRIDE_BOX/_INFLIGHT/_LOCK`、`adapter.HOOKS/COMMAND/_BASE_CLASSES/_MERGED_CLASSES`、以及 `_log_*_once` 这类**挂在函数对象上的限流戳**。**锁必须与它守的容器同源**（现在是两世代共写同一 dict、却各有一把 `_LOCK` ⇒ 互斥失效）。共享盒子的**键清单收敛到一处**（`_shared_box()`），并加断言「盒子键集合 == 声明集合」 | `git revert` |
| **A1 决定性实测** | 启动自检里打一行：`scope=<hermes_home_key> · manager=<id> · manager._hooks['pre_tool_call'] 长度 · 世代标记`（世代标记 = 本模块加载序号）；再在一次真机回合里统计**每个钩子的派发次数**。**先拿到「哪一份是活的、哪一份只留在平台上」的实测结论**，A2' 才允许动手 | 同上 |
| **A2'（取代 v1 的 A2）** | 按 A1 结论决定形态，候选：① 世代更替只影响「谁持有引用」，而状态已共享 ⇒ **记录结论、不加守卫**；② 若实测发现某世代零回调/平台被旧世代冻结 ⇒ 让**适配器按需解析共享状态**（而不是在 import 期绑定模块全局），并加「世代更替后第一帧仍能读到最新面板/页脚」的门禁 | 同上 |

| **A4 真机闭环** | 用 A5 或「用户正常使用时顺带一眼」拿到真机日志行，三症状逐条给「有/无」；**结案表只放脱敏行** | — |
| **A5 自触发能力** | 唯一需要用户做的：一次性 `lark-cli auth login`（设备码流程；用户身份；`~/.lark-cli/` 在仓库外、600 权限）。**用途/范围/撤销都写明**：只用于「以用户身份发消息触发真机回合」；撤销 = `lark-cli auth logout`。**它不是验证证据本身**（工具链），只是取样手段 | `lark-cli auth logout` |

## 4. Phase C：R3 完整版（每工具一行）—— 门槛更高了（v2）

**前置**：Phase B 全部完成；且 **A1 的世代结论**已明确（否则「钩子写一份、卡片读另一份」会让 C 的

2. 失败分类**必须解析 msg 内层 code**（`plan-v1:123-126`）+ append 形状的码**再取一次真机样本**；
3. **一次 `create` 可带多个元素**（省配额，P7 实测 5/10 个都 `code=0`）；
4. **行更新并入同一次 `batch_update`**（`plan-v1:193` 四条压预算措施之一，v1 只搬了三条）；
5. **运行时 create 是否吃 +1 序号空间**（附录 F 未答项；答错撞 `300317` ⇒ DEGRADE）——**先做一次真机探针回答它**；

8. **观感确认**（行级 vs 块级重绘差是唯一收益，只有眼睛能判）+ 改卡片结构后必须跑 `probe_render.py`；
